## 二、下一阶段候选（按优先级）

### M6-A. 桌宠系统深化（承接当前阶段）
- **台词分层**：按亲密度等级分档台词池（初遇时客气、挚爱时亲昵），按时段（早 / 午 / 晚 / 深夜）变化
- **差分扩展**：喂食时专属表情（吃东西）、升级庆祝动画、睡觉差分（深夜自动切换）、疲惫差分（长时间阅读后）
- **互动动作升级**：双击 = 摸头（专属飘心动画）；拖拽时桌宠"被拎起来"的摇晃感；久置不动打瞌睡
- **亲密度奖励**：解锁桌宠配饰 / 新的开屏立绘 / 专属阅读背景色
- **桌面小组件**（Android AppWidget）：桌宠 + 今日阅读时长，脱离 App 也能看到
- 预估工作量：1~2 个阶段迭代

### M6-B. 官方正版源评估（不稳定性根治）
- 评估路径：番茄小说 / 起点（需要对接官方开放平台或 Web 端 API）
- 现状：第三方克隆源 DNS 不稳定（如 bqgiu.cc 已挂），需要官方或长期稳定源兜底
- 备选：自建搜索聚合服务（多源健康检查 + 自动摘除死源）
- 预估工作量：1 个阶段迭代（调研为主）

### M6-C. 发现页 / 探索（阅读 3.0 explore 能力）
- 书源 explore 规则解析（分类 / 榜单 / 专题）
- 发现页 UI：分类 Tab + 排行榜 + 编辑推荐位
- 依赖：需要书源支持 explore 规则（阅读 3.0 标准）
- 预估工作量：1 个阶段迭代

### M6-D. 阅读体验补完
- **朗读（TTS）**：系统 TTS 接入，支持后台播报、章节自动连播
- **字体扩展**：允许导入自定义字体文件（.ttf）
- **阅读页眉脚自定义**：可以开关时间 / 电量 / 页码 / 章节名
- **屏幕方向锁定**（横屏阅读）
- 预估工作量：0.5~1 个阶段迭代

### M6-E. 数据与同步
- **WebDAV 备份**：书架数据 / 阅读进度 / 书签 / 桌宠等级全量备份与恢复
- **导出 / 导入**：书源导出（已有）、书架数据导出
- 预估工作量：0.5 个阶段迭代

### M6-F. 性能与工程化
- 启动速度优化（开屏到书架）
- 大书架（100+ 本）滚动性能
- CI 化：analyze + test + build 全流程脚本化（一键发布）
- 预估工作量：0.5 个阶段迭代

## 三、推荐路线

**推荐顺序**：`M6-A（桌宠深化，趁热打铁）→ M6-D（阅读补完，TTS 优先）→ M6-B（正版源调研）→ M6-C（发现页）`

理由：
1. 桌宠刚上线，趁热打铁做差分 / 台词扩展，用户感知最强；
2. 朗读（TTS）是阅读器刚需功能，技术路径清晰；
3. 正版源是长期稳定性问题，适合作为并行调研项；
4. 发现页依赖书源生态成熟度，放最后。

## 六、构建环境注意事项（踩坑记录）

### 内存不足会导致 AOT 编译崩溃
症状：
```
double free or corruption (fasttop)
Dart snapshot generator failed with exit code -6
Target android_aot_release_android-arm64 failed
```

原因：`free -m` 显示内存紧张（本机 11GB 总量，常占用 9.5~10.5GB），
多架构 AOT 编译（arm + arm64 并行）峰值内存超过可用量。

**解决**：
1. 清理 `/data/local/tmp` 的历史 APK；
2. `sync && echo 3 > /proc/sys/vm/drop_caches` 释放页缓存；
3. **改用单架构构建**：`flutter build apk --release --target-platform android-arm64`
   （设备为 arm64-v8a，只需这一个 ABI；APK 体积也从 55MB 降到 34.6MB）。

> 若需兼容 armv7 老设备，可改为 `android-arm,android-arm64`，但需先确保内存充足。

### 其他环境事实
- 设备 ABI：`arm64-v8a`（`ro.product.cpu.abilist`）
- 本机（OPPO/ColorOS）TTS：存在 `com.oplus.ttsaccessibilityengine` 引擎，
  但 `settings get secure tts_default_synth` 为 `null`（未设默认），
  另有 `com.heytap.speechassist`。App 会主动 `ttsInit` 并给出引导。
- 系统语言：`zh-CN`
