# 桌宠与 AI 阅读工作台：1.4.0

## 产品定位

桌宠负责轻量陪伴，阅读工作台负责可完成的任务。保留桌宠默认开启、全局关闭和阅读时独立开关。所有互动都应可退出，亲密度只使用既有的日上限规则，动作按钮不额外产出奖励。

AI 首页优先呈现能直接完成的阅读任务。继续阅读、全文关键词检索、书签笔记、阅读统计和书源检测不依赖模型；章节理解才使用模型。自由对话保留为独立入口。

## 本次实现

| 项目 | 行为 |
| --- | --- |
| 表情和动作 | 既有角色差分配合淡入、缩放过渡；余弦呼吸、点击弹跳、拖动倾斜和短时节拍舞蹈。没有替换角色画风或生成新素材 |
| 主动交互 | 长按桌宠或从设置打开面板，选择打招呼、摸头、跳舞、一起读书、休息；投喂沿用既有背包和等级规则 |
| 安静陪伴 | 不冒泡、不主动四处跑动；角色仍可交互 |
| 减少动画 | 可关闭柔和动画，并尊重系统减少动态效果设置；后台、隐藏和暂停期间停止循环动画与移动 |
| 临时暂停 | 暂停显示 15 分钟，可在设置面板提前恢复；自然到期按分钟检查刷新 |
| 继续阅读 | 从真实的最近阅读记录打开书籍与进度 |
| 原文检索 | 搜索本地 TXT/EPUB 与在线缓存；结果带出处和跳转位置，不自动联网补正文 |
| 章节分析 | 明确选择书籍，使用其当前阅读章节；提供摘要、人物关系、情节与伏笔解释三种任务 |
| 文本范围 | 本地模型最多使用当前章开头 700 字符，在线最多 6,000 字符；截断时标记为片段，不声称代表整章 |
| 在线确认 | 每次先显示来源、字符数、文本预览和接口地址；用户确认后才发送正文；不自动上传整本书或书架 |
| 模型回答 | 要求依据原文、附短引、缺乏依据时说明；模型可能出错，结果页提示核对原文 |
| 书签笔记 | 用户点击后才保存，带书名与章节来源；模型笔记可与同位置普通书签共存，同一次保存失败可重试，不覆盖原书签 |
| 自由对话 | 通过工作台右上入口打开；原有在线接口、本地模型和配置页继续可用 |

## 后续方向

1. 原文检索先建立本地索引与结果排序，再评估语义检索是否值得增加模型和存储负担。
2. 长章节采用按段分析与可核对引用，避免将截取的开头伪装成完整章节总结。
3. 多章笔记串联时要明确哪些章节被使用，并提供防剧透范围；当前只使用当前章的片段。
4. 角色动画优先调整节奏、动作切换和减少打扰，再考虑额外动作素材；本次动画使用既有图片的变换和表情过渡。

## 验证与边界

- 34 个选定用例通过，包含本次新增的 4 个测试：桌宠设置与动作、缓存片段范围、同位置笔记共存、无模型工作台。
- Flutter 静态检查无问题。
- 本机 mobile-mcp 未发现在线设备，原 MuMu 端口重连被拒绝；设备上的动画观感和实际模型生成质量尚未验收。
- 未下载新的大模型，未使用用户的真实 API Key 发起付费模型请求。在线分析行为受预览确认控制，但模型质量仍取决于已配置模型。

- Android arm64 release APK 构建成功：1.4.0+65，约 49.1 MB。
